# NOCTURNE / X-Nekama

架空のAIキャラクターのXアカウントについて、お手本投稿の分析、画像スタイルの管理、投稿案と画像の生成、レビュー、予約投稿を行う管理サイトです。Xの実際のプロフィールに「架空AIキャラクター」の明示があることを接続時と投稿直前に確認します。

## 実装済み

- 複数のXアカウントを登録。XActionsのログインまたはブラウザから取得したCookieで接続し、セッションを暗号化保存
- お手本アカウントの公開投稿をXActionsからページ送り取得。保存した投稿をGeminiで文体分析
- キャラごとの顔の基準画像と、プリクラ・BeReal風・自撮り・鏡撮り・他撮りの参考画像を登録
- Geminiで翌日以降の週次投稿案と、顔の基準画像・撮り方の参考画像を用いた画像を生成
- X風投稿一覧、カレンダー、個別編集、レビュー、予約、投稿履歴・失敗履歴
- 運用ONのキャラは次週の投稿案を定期補充。完全自動モードをONにすると、生成画像の準備・予約も自動で進行
- 画像生成失敗やX投稿が曖昧な場合は、自動再送しない。X上の投稿状態を確認してから復旧

XActionsのHTTPクライアントとGraphQL更新追従コードを `vendor/xactions/` に収録しています（Apache-2.0）。収録時の上流コミット: `nirholas/XActions@24eed62ec87de80d33d280dce081f9ccea5c0ba8`。Xの変更への追従には、上流の更新を定期的に取り込む必要があります。X-Bunsekiは参考にしましたが、検索監視や学習モデルのコードは流用していません。

## 起動

Node.js 24以上で依存パッケージのインストールは不要です。

```sh
cp .env.example .env
# .env に GEMINI_API_KEY を設定
npm start
```

初回起動時の管理パスワードがサーバーの起動ログに出ます。以降は `data/.admin-password` に保持されます。本番では `ADMIN_PASSWORD` と32文字以上の `APP_SECRET` を環境変数で設定し、**`data/` を永続化**してください。`data/` を消すと投稿・画像・セッションと生成された暗号鍵を失います。`HOST=0.0.0.0` で公開する場合、TLS終端のあるリバースプロキシとアクセス制限を設けてください。

Docker利用時は `docker build -t nocturne .` でイメージを作り、永続ボリュームを `/app/data` にマウントして環境変数を渡します。**常時稼働するNodeサーバーが必要**です。スリープする無料Webサービスや一時的なファイルシステムのサーバーレス環境では、予約が時刻通りに動きません。複数レプリカ運用は想定していません。

## 初期設定の順番

1. 管理画面で架空AIキャラクターとXユーザーIDを登録する。プロフィール文に「架空AIキャラクター」を含める。
2. 管理画面からXアカウントに接続する。通常はXパスワードでログイン、追加認証がある場合は `auth_token` と `ct0` を含むログイン済みCookieを使う。パスワードは保管しません。プロフィール文をXへ反映し、確認してから接続します。
3. お手本アカウントを追加して公開投稿を取得し、文体を分析する。
4. キャラの基準画像と、使いたい写真カテゴリのお手本画像を登録する。基準画像は実在人物の同意を得たものか架空人物の画像を使用する。
5. 投稿案を作成・確認する。テキストのみの投稿なら画像登録は不要。画像付きは画像生成後に確認して予約する。
6. 無人で運用する場合はアカウント設定で「自動投稿」と「完全自動モード」をONにする。完全自動では生成内容の事前確認を省略するので、最初はレビュー運用で品質を確認してください。

X上で使える公開投稿の範囲とX側の取得制限に左右されるため、参考アカウントの過去投稿を**必ず全件取得できる保証はありません**。画面で20〜5000件の取得上限を指定できます。取得・生成・投稿が成功したかは、外部サービスの実アカウントとGeminiキーを登録した後に確認してください。

## 環境変数

| 変数 | 用途 |
|---|---|
| `GEMINI_API_KEY` | Google AI Studioで発行するキー。サーバーだけに設定 |
| `GEMINI_TEXT_MODEL` | 投稿・文体分析モデル。初期値 `gemini-2.5-flash` |
| `GEMINI_IMAGE_MODEL` | 画像生成モデル。初期値 `gemini-3.1-flash-image` |
| `ADMIN_PASSWORD` | サイト管理用パスワード。省略すると初回に自動生成 |
| `APP_SECRET` | 暗号鍵の材料。省略すると `data/.app-secret` に自動生成 |
| `DATA_DIR` | SQLite DBと画像の保存先。初期値 `./data` |
| `HOST`, `PORT` | バインド先。初期値 `127.0.0.1:3000` |

APIキーとXのCookieはGitHubのファイルに追加しないでください。画像生成にはGemini側の利用枠と料金体系が適用されます。生成画像がXの画像上限を超える場合はレビュー待ちとしてエラーが表示されます。

## 検証

`npm test` は認証、データ保存、AI表記の必須チェック、未接続アカウントの予約拒否、画像保存・取得を検証します。キーと実アカウントを使ったX投稿およびGeminiの出力品質は自動テストに含まれません。
