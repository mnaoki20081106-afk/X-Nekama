# NOCTURNE / X-Nekama

架空のAIキャラクターのXアカウントについて、お手本投稿の分析、画像スタイルの管理、投稿案と画像生成プロンプトの作成、レビュー、予約投稿を行う管理サイトです。Xの実際のプロフィールに「架空AIキャラクター」の明示があることを接続時と投稿直前に確認します。

## 実装済み

- 複数のXアカウントを登録。**自動投稿はX公式API v2のOAuth 2.0 user access tokenを推奨**し、トークンを暗号化保存。XActionsのCookie/ログイン接続は参考投稿取得などの互換用として残す
- お手本アカウントの公開投稿をXActionsからページ送り取得。保存した投稿をGrokで文体分析
- キャラごとの顔の基準画像と、プリクラ・BeReal風・自撮り・鏡撮り・他撮りの参考画像を登録
- Grokで翌日以降の週次投稿案を生成。画像付き投稿はGrok Imagineで直接生成でき、顔・スマホケース・服装・背景・撮影スタイルの参考画像を最大5枚まで利用
- X風投稿一覧、カレンダー、個別編集、レビュー、予約、投稿履歴・失敗履歴
- 運用ONのキャラは次週の投稿案を定期補充。自動画像生成をONにすると画像付き投稿もGrok Imagineで作成。自動承認をONにすると、画像が準備できた投稿を予約キューへ送る
- X投稿が曖昧な場合は、自動再送しない。X上の投稿状態を確認してから復旧
- 投稿キューはSQLiteへ永続化し、429・送信前の一時的通信障害だけを最大3回まで段階的に再試行。Xへ送信した後の通信断・5xx・投稿ID不明は重複防止のため要確認へ送る
- 同一アカウントの投稿処理をロックし、同じ本文の予約・送信中・直近24時間の再投稿を検出して誤った重複投稿を防止

XActionsのHTTPクライアントとGraphQL更新追従コードを `vendor/xactions/` に収録しています（Apache-2.0）。これは参考投稿取得と旧セッション互換用です。**自動投稿の本命はX公式API v2**です。収録時の上流コミット: `nirholas/XActions@24eed62ec87de80d33d280dce081f9ccea5c0ba8`。X-Bunsekiは参考にしましたが、検索監視や学習モデルのコードは流用していません。

### X投稿の推奨経路

実運用では **X公式API v2を最優先**します。アカウントにOAuth 2.0 user access tokenが登録されている場合、投稿処理は自動的に公式APIへ切り替わります。

- 本人確認: `GET /2/users/me`
- 画像アップロード: `POST /2/media/upload`
- 投稿: `POST /2/tweets`
- Grok Imagineで生成した画像を添付する場合は `made_with_ai: true` を送信
- 公式API tokenがない既存アカウントだけ、互換目的でXActionsのセッション送信へフォールバック

Xの自動化ルール上も、API外のスクリプト自動化より公式API経由を使用する方が適切です。Developer Console側で、利用する機能に必要なユーザー認可権限を付けたOAuth 2.0 tokenを発行してください。権限不足の場合はX APIの401/403をそのまま要確認として扱います。

### 投稿キューの安全設計

自動投稿の状態管理は、公開プロジェクトの **Postiz** のXプロバイダ/ワークフロー設計と **Tweepy** のレート制限エラー処理を参考にしています。コードの直接流用ではなく、以下の考え方をX-Nekama向けに実装しています。

- 予約時にキュー識別子と本文フィンガープリントを保存
- 同一アカウントは送信処理を直列化し、複数ワーカー相当の競合でも二重送信しにくくする
- HTTP 429 / rate limit は待機して再試行。Xの rate-limit reset 時刻が取得できる場合はそれを優先
- 画像アップロード前後など、投稿作成前に失敗した一時的通信障害は安全な範囲だけ再試行
- 投稿作成リクエスト送信後の通信断・5xx・投稿ID不明は、成功済みの可能性があるため自動再送しない
- サーバー再起動時に `publishing` だった投稿も自動再送せず、X上で結果確認してから復旧
- 同一本文の予約/送信中、または直近24時間の投稿済みを検知して重複を止める

X側には一般的な投稿作成のidempotency keyがないため、X-Nekama内部のキュー識別子だけで外部投稿の重複を完全保証することはできません。そのため「送信結果不明なら止める」ことを優先しています。

## 起動

Node.js 24以上で依存パッケージのインストールは不要です。

```sh
cp .env.example .env
# .env に XAI_API_KEY を設定
npm start
```

初回起動時の管理パスワードがサーバーの起動ログに出ます。以降は `data/.admin-password` に保持されます。本番では `ADMIN_PASSWORD` と32文字以上の `APP_SECRET` を環境変数で設定し、**`data/` を永続化**してください。`data/` を消すと投稿・画像・セッションと生成された暗号鍵を失います。`HOST=0.0.0.0` で公開する場合、TLS終端のあるリバースプロキシとアクセス制限を設けてください。

Docker利用時は `docker build -t nocturne .` でイメージを作り、永続ボリュームを `/app/data` にマウントして環境変数を渡します。**常時稼働するNodeサーバーが必要**です。スリープする無料Webサービスや一時的なファイルシステムのサーバーレス環境では、予約が時刻通りに動きません。複数レプリカ運用は想定していません。

### Railwayに公開する場合

1. GitHubリポジトリ `mnaoki20081106-afk/X-Nekama` をRailwayの新規サービスとして接続する。ルートの `Dockerfile` を使用する。
2. サービスに永続ボリュームを追加し、マウント先を **`/app/data`** にする。レプリカは1、Serverless（自動スリープ）は無効にする。
3. Variablesに `XAI_API_KEY`、十分に長い `ADMIN_PASSWORD`、32文字以上のランダムな `APP_SECRET` を登録する。値をGitHubやチャットに貼らない。`HOST` と `DATA_DIR` はDockerfile内で設定済み。
4. 公開ドメインを生成し、`/api/auth` が応答することを確認する。管理画面へログインし、Xプロフィールとアカウント接続を行う。

この構成には常時稼働するサービスと永続ボリュームの利用料金がかかる可能性があります。Railwayのボリュームはデフォルトでroot所有のため、Docker起動時に `/app/data` の所有者を調整してから一般ユーザーでサーバーを起動します。データ保護のため、ボリュームのバックアップも設定してください。

## 初期設定の順番

1. 管理画面で架空AIキャラクターとXユーザーIDを登録する。プロフィール文に「架空AIキャラクター」を含める。
2. 管理画面からXアカウントに接続する。**推奨はX Developer ConsoleでOAuth 2.0のuser access tokenを取得して登録する方法**です。X-Nekamaは `/2/users/me` で接続先を照合し、投稿時は公式 `/2/media/upload` と `/2/tweets` を利用します。参考投稿取得など互換機能が必要な場合のみ、従来のXパスワード/Cookie接続を追加できます。パスワード自体は保存しません。
3. お手本アカウントを追加して公開投稿を取得し、文体を分析する。
4. キャラの顔・外見基準画像、スマホケース、服装、アクセサリー、背景、撮影スタイルのお手本を登録する。人物資料は架空人物か、本人の同意を得たものだけを使用する。
5. 投稿案を作成・確認する。画像付き投稿は「Grokで画像生成」で直接生成できる。手元の画像へ差し替えることも可能。画像が未設定の画像付き投稿は予約できません。
6. 「画像付き投稿はGrok Imagineで自動生成」をONにすると週次生成時に画像も作成する。「自動承認」をONにすると、画像が準備できた投稿を予約キューへ送る。

X上で使える公開投稿の範囲とX側の取得制限に左右されるため、参考アカウントの過去投稿を**必ず全件取得できる保証はありません**。画面で20〜5000件の取得上限を指定できます。取得・生成・投稿の実サービス接続は、XアカウントとxAI APIキーを設定した環境で確認してください。

## 環境変数

| 変数 | 用途 |
|---|---|
| `XAI_API_KEY` | xAI Consoleで発行するキー。サーバーだけに設定 |
| `XAI_TEXT_MODEL` | 投稿・文体分析モデル。初期値 `grok-4.7` |
| `XAI_IMAGE_MODEL` | 画像生成モデル。初期値 `grok-imagine-image-2.0` |
| `XAI_IMAGE_RESOLUTION` | 生成解像度。初期値 `1k` |
| `XAI_IMAGE_QUALITY` | 画像品質。初期値 `medium` |
| `ADMIN_PASSWORD` | サイト管理用パスワード。省略すると初回に自動生成 |
| `APP_SECRET` | 暗号鍵の材料。省略すると `data/.app-secret` に自動生成 |
| `DATA_DIR` | SQLite DBと画像の保存先。初期値 `./data` |
| `HOST`, `PORT` | バインド先。初期値 `127.0.0.1:3000` |

APIキーとXのCookieはGitHubのファイルに追加しないでください。Grokの文章生成はResponses APIを `store: false` で利用し、通常のGrokチャット履歴や会話継続用のサーバー保存は使用しません。Grok Imagineの生成結果は一時URLから直ちに取得し、X-Nekamaのデータ領域へ保存します。xAI APIは別途、既定で監査目的の一時保持があるため、保持自体を無効化したい場合はxAI Console側のZero Data Retention設定を利用してください。手動で差し替える投稿画像は各5MB以下です。

## 検証

`npm test` は認証、データ保存、AI表記の必須チェック、未接続アカウントの予約拒否、画像保存・取得に加え、429・一時障害・送信結果不明の分類、バックオフ、本文フィンガープリントを検証します。キーと実アカウントを使ったX投稿およびGrokの出力品質は自動テストに含まれません。
